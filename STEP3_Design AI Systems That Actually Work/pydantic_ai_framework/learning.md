The High-Level Architecture (The "Pipeline")Unlike a simple chatbot, an AI Agent is a pipeline. Data flows through specific stages, transforming from raw text into structured, verified facts.The 4-Stage FlowInput Stage (User & Context):The user asks a question (e.g., "Is the earth flat?").We attach a "Notebook" (Context) to track the agent's actions (e.g., search count, session ID).Reasoning Stage (The Brain):The LLM analyzes the request.If it needs external data, it pauses generation and requests a Tool Call (e.g., search_web).Execution Stage (The Tool):Python code executes the actual work (e.g., DuckDuckGo search).It updates the Context (increments search counter) and returns raw text to the LLM.Verification Stage (The Validator):The LLM proposes a final answer based on the tool output.Our Validator Function intercepts this proposal.It checks against strict rules (e.g., "Must have a URL", "Must not be empty").It either Accepts the answer or Rejects it (forcing the LLM to retry).2. State Management: Controlling the Agent's MemoryQuestion: "Can we control the state of the agent using data from Pydantic classes?"Answer: Yes. This is called Dependency Injection.The Concept: "The Notebook"Think of AgentContext as a physical notebook you hand to the agent before it starts a job.Per-Run State: If you create a new notebook (AgentContext()) for every agent.run(), the agent starts fresh every time.Session State: If you keep the same notebook instance and pass it to multiple agent.run() calls, the agent "remembers" what happened before (e.g., "I already searched 3 times in the previous turn").Implementation RuleDefine it: Create a Pydantic model (class AgentContext).Inject it: Pass it into deps during .run().Use it: Access it in tools via ctx.deps.Python# Control the state explicitly
my_session = AgentContext(search_count=2) # "Pre-load" the state!

# The agent thinks it has already searched twice!
result = agent.run_sync("Query", deps=my_session)

The "Validator Dilemma": ctx vs. ArgumentsQuestion: "When can I know when to use ctx or the validator params in a tool?"Use this Rule of Thumb:Scenario A: The Tool needs "World Knowledge" (Use ctx.deps)If the function needs data external to the LLM's current thought process (Database connections, API Keys, User IDs, Session Counters), use ctx.deps.Example: search_web(ctx, query) -> Needs ctx to increment the search_count.Scenario B: The Validator needs "Proposed Answers" (Use Arguments)If the function is checking the Result the LLM just generated, use Arguments.The LLM is "calling" your validator function to hand over its work. It passes the work as arguments.Example: verify_evidence(claim, verdict, ...) -> The LLM is saying "Here is the claim and verdict I found."Featurectx.depsFunction ArgumentsSourceYou (The Engineer)The LLM (The Brain)ContentDBs, Configs, StateClaims, Verdicts, ReasoningDirectionInput (Into the Agent)Output (From the Agent)4. The Testing Strategy: "Mocking the Brain" 🧠Testing search agents is hard because web results change. We solve this by Mocking the Brain.We don't test "Did DuckDuckGo work?" (That's their problem).We test "Did my Agent ask for DuckDuckGo correctly?"The 2-Turn SimulationTo test a tool-using agent, you must simulate a conversation history:Turn 1 (The Request):Agent: "I need to verify this claim."Mock Brain: "Okay, I am calling tool search_web with query 'Earth shape'."Check: Did the agent pick the right tool?Turn 2 (The Synthesis):Agent: "I have the search results."Mock Brain: "Great. Here is the final FactCheckResult based on that data."Check: Did the Validator accept the result?Why we do this?Speed: Tests run in milliseconds.Cost: $0.00 (No OpenAI calls).Stability: The test passes even if the internet is down.5. Summary Checklist for Junior Engineers ✅When building a new Agent, follow this checklist:Define the Structure:What goes in? (deps / Context)What comes out? (ResultModel)Build the Guardrails:Write a Validator Function that takes the ResultModel fields as arguments.Check for "lazy" answers (e.g., missing URLs, empty evidence).Equip the Tools:Wrap external APIs (like Search) in simple Python functions.Format the output as a Clean String for the LLM.Test the Logic:Write a test with a Mock Brain.Simulate the "Happy Path" (Tool Call -> Final Result).Simulate the "Edge Case" (e.g., Search Limit Reached).You have now mastered the fundamental loop of AI Engineering: Design -> Guardrail -> Implement -> Mock Test.
